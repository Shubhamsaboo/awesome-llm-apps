# 高效实施、复验与收尾

开始规划、准备最终审查或发生返工时读取。保留所有必需技能和真实验收；优化的是重复工作，不以时间预算豁免失败场景。

## 开发前准备

- 在实际执行环境中确认工作目录、Node/包管理器、所选脚手架版本及项目缓存可用；先运行最小正式构建。记录可重用命令与目录，后续不凭记忆重写路径。不固定某台机器的版本、端口或绝对路径。
- 从实际读取的必需技能提取会影响实现的硬约束，例如异步消息响应、权限、存储和代码规范；能用现有 lint/静态检查发现的，在第一次浏览器验收前检查。规范来自当前技能，不能误说成浏览器平台强制规则。
- 先验证所选 MCP 能真实安装扩展、触发原生入口并读取结果；复制、截图或重启等特殊能力仅在需求涉及时早测。替代默认 Playwright MCP 仍须按依赖规则取得用户选择。版本和环境未变时复用已核实结果。
- 新建或改变使用流程先实际执行 product-designer，按 [产品使用闭环](product-loop.md) 定义继续使用与恢复，验收包含连续两轮；效率优化不得省略这一体验关卡。
- 将 AC 写成“前置状态 → 实际动作 → 预期 → 证据”，提前覆盖核心路径、故障恢复及产品承诺的持久化。涉及设置时用非默认值；涉及清空、并发保存或跨浏览器重开时明确列项。不要等最终审查才发明测试范围，也不为简单功能增加无关矩阵。

## 拆票与批次

复杂插件仍执行 setup → to-spec → to-tickets → implement。按用户功能、独立风险和模块契约拆票，不按文件数量或同一种机制支持几个网站拆出重复流水线。

主代理可合并尚未关闭、同一共享实现且需要一起验证的票，保留原 AC 映射与模块所有权，更新依赖，不删需求。每张实际实施票仍需真实验收和 code-review。无依赖且写入范围不冲突的模块可独立开发；有依赖的工作不得因合批绕过前置条件。

同一固定候选的一次双轴审查可以覆盖多个就绪票及最终版本，前提是明确列全基线、差异、规格和 AC，并分别回填结论。最终跨模块验收票仍保留，但可直接引用同一候选、同一实际操作的证据，不为工单编号重复安装和操作。不能用分模块检查代替缺失的整体路径。

## 按影响复验

| 改动 | 必需工作 |
| --- | --- |
| 仅文档、工单状态、会话归档，运行包字节未变 | 校核记录、链接与原指纹；不重跑产品测试、浏览器或已通过的代码审查 |
| 局部界面或独立逻辑 | 正常构建与针对性检查；加载新候选，验证实际原生核心路径和受影响操作；涉及保存则重开验证 |
| 权限、入口、消息、共享状态、存储、过滤规则或依赖变化 | 对新候选验证相关跨模块路径、失败恢复及适用持久化；影响无法界定时扩大回归 |
| 仅打包，ZIP 内相对路径和字节均与已验收目录相同 | 本地交付核对文件清单与哈希；有商店发布需求时仍执行发布参考要求的 ZIP 解压加载验证 |

每次运行包变化都生成新指纹，最终候选始终必须有实际加载、原生入口、核心流程和适用重开的当前证据。复用未变模块的历史深测时，记录旧候选、覆盖场景、未变的依赖及影响判断，作为历史证据单列；不得修改旧指纹或把未重跑场景标为新候选实测。属于当前最终验收必需场景的，仍须在当前候选实际执行。现有门禁不支持用历史通过记录冒充当前通过。

## 审查前备齐，失败后只修缺口

准备固定基线、全部差异（含新文件）、AC、当前成品、真实证据和门禁报告，以及本次交付要求的 ZIP 与 FINAL_REPORT 草稿。报告写明待审查，不预填通过。用机器检查先发现文件缺失、JSON 无效、必需场景 ID 缺失和哈希不符，再交 code-review；静态检查单列，不能填成必需真实浏览器场景。

双轴审查必需执行。功能/安全/数据问题必须修复复验；明确的项目硬规范也必须满足，但应在前置检查中发现。建议性重构或纯偏好不自动扩大交付范围。整改复审聚焦原 findings、修复差异及受影响 AC，不因状态文档变化重启整个审查周期。

遇到已知工作目录或证据格式错误，diagnosing-bugs 可复用已确认根因，修正调用并验证结果，不重做无关产品实验。连续出现同类返工时，主代理应检查编排、模板和依赖是否有问题，合并重复动作；不得降低预期来结束任务。

## 一次收尾与时间记录

只有目标内 AC、当前验收门禁和双轴审查通过且交付文件齐全，才进入收尾。一次更新权威工单、简短状态索引、最终报告和本地版本记录后交付；不再增加全文日志、形式化清理、新审查或产品测试。发现实质缺陷则返回对应节点。

规格和工单为权威正文，state 仅索引，报告链接证据；不要手工维护多份相同状态。已有状态工具可用时调用它更新索引；没有工具则一次性更新必要字段，不临时开发一套任务平台。结束后不为“再确认一次”循环运行同一套检查。

记录首次开始、各阶段结束及中断/恢复时间。多项目并行时区分整体历时和各项目历时，不能相加冒充用户等待时间。预计明显超出计划或用户催促时，立即报告已完成成品、剩余具体问题，并缩减无关范围与重复步骤；不凭空承诺剩余分钟数。

## 用户要求独立 CLI 或完整会话时

仅在本次有此要求时启用。每个项目保留独立目录与原会话 ID，按用户指定模型和强度运行；说明配置/历史/profile 隔离与操作系统隔离的区别。记录控制消息是否真正进入会话；排队不等于已送达，不把中断重启当作常规消息通道。恢复时只传缺口和下一动作，不重复初始化或读取全部技能。

从原始公开消息生成 conversation.md，明确标注用户原话、主线程委派、恢复指令和 AI 回复；保留原始主/子会话、工具事件及校验清单，不导出认证文件或把内部推理展开成公开对话。无法取得原始内容时标明缺失，不能补写。运行中采用增量或按需快照，结束后做一次完整导出和一致性核对；避免多写入者覆盖同一个 Markdown。该记录不自动代表包含桌面主线程全部聊天。
