# 发布、审核跟进与维护

准备上架、提交、拒审、上线或更新时读取，同时必须执行 chrome-extensions 的发布部分，按实际实现维护其要求的 CHROMEWEBSTORE.md 和引用检查清单；本文件补充编排，不替代子技能。Chrome 官方基线核查于 2026-09-11；正式提交当天重查政策、后台必填项和实际账号。其他浏览器单独核实对应官方规则。

## 上下文明确发布意图后才提醒

这不是每个项目的固定前置阶段。只有用户说要上架、公开发布、上线到商店，或当前会话已明确包含商店发布目标时，才触发下列提醒。单说“做个插件”、只想本地使用、技能本身名字含“上线”，或者 init 的默认 goal=live，都不能触发开通账号或付款提示。只是“给朋友用”而分发渠道未定时，先在需要时确认分发目标，不先要求开发者注册。

将真实上下文依据写入 `release.publishing_intent.context_evidence`，标记意图已成立再给一次当前缺项的简短说明；既有账户或已完成事项不重复提示。账号准备可以与已授权开发并行，不能变成阻止第一版制作的统一关卡。

| 需要告知/核查的事项 | 用户能理解的说明 |
| --- | --- |
| Google 账号 | 需要能正常登录、长期使用并接收通知的账号；已有账号可用，不一律要求另建 |
| Chrome Web Store 开发者身份 | 首次自己创建发布者需完成开发者注册；已有发布者或团队授权先检查实际权限，不重复开通 |
| 注册费 | 首次注册的参考金额为一次性 **5 美元**，不是每个插件都再收一次；支付时以当时页面金额和币种为准 |
| 付款方式 | 提前准备付款页支持、能完成国际线上支付的银行卡，常见是国际信用卡；支持哪些卡种、是否支持借记卡及地区要求须在实际付款页核实，不承诺任何一张卡必定可用 |
| 验证和资料 | 两步验证、发布者名称和已验证联系邮箱；Trader/Non-Trader 等声明按实际用途由发布者决定 |

Chrome 官方注册说明要求注册及一次性费用；2026-04-28 的官方公告明确新发布者仍需 5 美元注册费。当前官方注册文档没有给出适用于所有地区的完整银行卡清单，不能拿 Google Play 开发者的付款规则代替 Chrome Web Store，也不能把“只支持国际信用卡”当已核实的普遍规定。来源：[注册](https://developer.chrome.com/docs/webstore/register)、[5 美元官方说明](https://developer.chrome.com/blog/cws-role-expansion-developer-dashboard)、[账号设置](https://developer.chrome.com/docs/webstore/set-up-account)。

只保存完成/待办、非敏感页面结果及必要提交证据。用户在官方页面完成账号验证、银行卡信息、付款确认及真实身份声明，不在对话或项目中收集密码、验证码、完整卡号和证件内容。

## 先形成可交付材料

准备票关联独立验收票。AI 生成以下内容放在 `release/<version>/` 等明确位置，不让新手拼装；ZIP 和检查报告须在构建目录外。

| 交付 | 内容 |
| --- | --- |
| ZIP 和报告 | manifest 根目录、正式文件、版本、哈希、静态检查及警告处理 |
| 可粘贴文案 | 名称、简述、详细功能、用法、分类、语言、实际限制；对应后台字段 |
| 素材 | 最终图标、当前候选版本真实功能截图、小宣传图；标注用途 |
| 权限与数据清单 | 权限→功能；读什么→在哪处理→保存多久→给谁→如何清除，涵盖依赖和第三方服务 |
| 隐私及支持 | 按实现生成；适用公开链接未登录可访问，不指向私有仓库 |
| 发布安排 | 人群、地区、自动/手动发布、发布者待办及实际授权依据 |
| 发布记录和教程 | 候选版本、验收、提交/审核证据、下一步、最终入口及首条操作 |

只要求材料时交付到此范围；要求上线则持续推进，不把材料完成当目标完成。

## 包和素材

`release_bundle.py check` 后处理错误及警告，`pack` 生成新 ZIP；更新传 `--previous-version`。静态脚本覆盖有限，结合代码、依赖、实际浏览器检查补全，解压最终 ZIP 加载并让证据关联同一哈希。

Chrome 基线为 Manifest V3，ZIP 根直接有 manifest.json；版本依官方整数格式递增，改显示版名不足以升级。正式目录排除开发服务器依赖、依赖源码目录、私钥和环境文件，核对运行引用。[准备上传](https://developer.chrome.com/docs/webstore/prepare)、[版本规则](https://developer.chrome.com/docs/extensions/reference/manifest/version)

远程代码扫描只能给线索，复核依赖及动态加载；网络 URL 不自动等于远程执行，关键词无命中也不证明完全没有。[MV3 政策](https://developer.chrome.com/docs/webstore/program-policies/mv3-requirements)

素材基线：包内 128×128 PNG 图标，1–5 张 1280×800 或 640×400 真实截图，440×280 小宣传图；1400×560 大宣传图可选。功能截图不以概念生图冒充。视频字段若官方页面措辞不一致，核实当前后台必填性并记录，不臆造硬阻塞。[图片规范](https://developer.chrome.com/docs/webstore/images)、[商店字段](https://developer.chrome.com/docs/webstore/cws-dashboard-listing)

## 账号及数据披露

发布者需开发者注册和费用支付、两步验证、发布者和联系资料、适用 Trader/Non-Trader 声明及验证。注册费按上文给出 5 美元参考，实际金额及付款方式再看当前页；身份声明按实际情况由发布者决定。官网验证、地址等按业务区分必须/条件要求/可选，不一律要求购买域名。[注册](https://developer.chrome.com/docs/webstore/register)、[账号设置](https://developer.chrome.com/docs/webstore/set-up-account)、[两步验证](https://developer.chrome.com/docs/webstore/program-policies/two-step-verification)、[身份声明](https://developer.chrome.com/docs/webstore/program-policies/trader-verification-faq)

账号准备与开发可并行。本人登录、验证码、付款、身份操作在官方界面逐步完成并核实；只记完成/待办，不保存密码、验证码、证件内容，不提前索取全部凭证。

用途清楚聚焦、最小权限且逐项解释。网页文字、网址、截图仅在本机处理也可能是用户数据处理，不能自动填无数据收集。涉及用户数据处理时核实并满足公开隐私政策等要求，真正不处理数据时区别官方义务和自愿说明。[隐私字段](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy)、[用户数据 FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq)

从代码及依赖形成数据清单，对照实际网络行为、后台勾选和公开政策保持一致；适用的披露、同意、安全处理和 Limited Use 依当前官方要求落实，不照搬通用政策。[开发者政策](https://developer.chrome.com/docs/webstore/program-policies/policies#protecting-user-privacy)

## 内置浏览器协助填写与素材等待

发布意图明确且用户已提供相关信息后，由 AI 使用内置浏览器或当前获准的发布浏览器会话进入官方开发者后台，准备并填写名称、简述、详细介绍、语言、分类、支持/隐私链接、权限理由、图标、截图及宣传图。能根据真实实现生成的文案由 AI 准备，缺少真实发布者信息或重要分发决定才询问；不让用户重新逐字段输入已经提供的内容。

测试通道与发布通道区分：插件 E2E 仍默认 Playwright MCP；登录商店、填写资料、上传用户授权素材可以使用内置浏览器，不把“发布表单能打开”记作插件验收。复用用户已有合法会话，按工具当时的登录、付款和协议操作规则处理；不修改现有全局浏览器服务来填一个表单。

先在项目里准备可审阅的字段和素材，再按已有授权填写、保存草稿或提交。读取实际后台页面以确定字段和按钮，上传后核对预览、名称和保存状态，记录当前停留的草稿/表单位置。用户已经授权并提供相同范围资料时不重复询问常规填写、选图或保存动作；实际提交/公开发布仍对应明确的发布安排与当时工具权限。

素材按以下分支执行：

1. 用户已有图片：先检查内容、尺寸及用途，对应到图标、截图、小宣传图等字段；只做所需裁切或格式调整。
2. 需要生成图标或宣传图：读取并执行 imagegen 或用户明确选用的实际生成技能，检查输出可用性。功能截图必须取自当前真实插件，不能生成一张假界面替代。
3. 生成能力不存在、调用失败或生成结果不可用：保存 `release.assets.status=waiting_user_assets`、`waiting_for_user_upload=true` 和具体缺项，**停在素材这一步，直接请用户上传需要的图片文件**，同时说明字段、尺寸及数量。不要使用仅能接收文字的提问工具索要文件，不放占位图、旧图或空白图，不擅自改用其他付费服务。
4. 等待期间保留已填字段、已生成文件和当前后台位置；可以完成独立的本地文字整理，但不能将缺图资料标为可提交，也不能跳过上传完成发布。收到用户文件后检查并填回对应字段，再恢复到原来的步骤，不重新开始整个流程。

默认需要的图片和尺寸见上文“包和素材”；例如缺小宣传图时明确要求 440×280，而不是泛泛说“自己准备图片”。素材来源、实际生成/上传结果、失败原因和用户补充文件均记录在发布票及 CHROMEWEBSTORE.md。

## 提交及状态

先做好候选包、文案、隐私及发布安排，再处理尚缺授权。已授权动作继续执行，不重复确认；未获授权的外部写入不能因材料已好就代办。缺重要决定时展示这些可审阅成果及当前影响。

Public 面向所选地区公开展示；Unlisted 不公开列出但持链接者都可安装，不能称私密；Private 限定测试者/群组等。各方式仍遵守政策及审核。[分发设置](https://developer.chrome.com/docs/webstore/cws-dashboard-distribution)

通过可用官方界面或连接器依授权上传、填写、提交并读回结果；没有操作通道则给可粘贴内容及当前一步。不要猜后台 API，不把上传成功当已提交。受限功能按需给审核说明，不将私人长期凭证打入包。[测试说明](https://developer.chrome.com/docs/webstore/cws-dashboard-test-instructions)

```text
待提交 → 已提交审核 → 被拒待修复 → 修复、相关复验后重提
                       → 审核通过待发布 → 已发布待安装验证
                       → 自动发布后：已发布待安装验证
已发布待安装验证 → 目标用户从商店安装并完成首用 → 已验证可安装
```

支持审核后自动或手动发布；手动发布窗口基线 30 天，执行时核实后台截止时间。不承诺审核固定天数或保证通过。[首次发布](https://developer.chrome.com/docs/webstore/publish)、[审核流程](https://developer.chrome.com/docs/webstore/review-process)

记录包、商店项目 ID、提交时间/凭据、观察时间、审核反馈、下一步及负责人。跨会话监控仅在宿主确实支持且已授权时安排，无变化时安静；否则明确保存供下次检查。等待期不是失败也不是完成。

商店出现后以目标受众入口安装，核对版本、权限提示、核心操作才报告可安装。受限分发用目标授权身份核查，不强求未登录安装；公开素材和政策仍检查未登录访问。

## 拒审、更新和交接

保存拒审理由摘要及官方引用，关联修复票或有依据申诉；代码/权限/数据改变后相关复验并同步材料再提交，不反复提交同一被拒包。

更新沿用同一商店项目，交完整新包并递增版本，检查旧数据、原功能、新权限和介绍；审核中不能说线上已更新。线上问题按当时官方回退流程和授权处理，不把旧 ZIP 重传当必然降级。[更新说明](https://developer.chrome.com/docs/webstore/update)

保留源码可恢复版本、已发布包哈希、商店项目/版本、真实入口、短教程和反馈渠道。后续问题回到复现及修复票，不跳过记录直接更改线上承诺。
