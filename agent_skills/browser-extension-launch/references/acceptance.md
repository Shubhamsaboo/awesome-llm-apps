# 真实使用与独立验收

**未通过真实验收，不得称插件可用、交付完成或关闭实施票。** 这适用于首次可用版、每张实施票、每个实现示例和最终发布候选包；用户明确只要源码或中止工作时，才可按该范围交出标为未验收的源码。

首条功能实现后立即做票内真实检查，版本发布前有独立总验收票。独立指范围、记录与复核分开，不能用实施自述替代。支持代理时让另一代理拿规格、候选包及已验证的真实浏览器能力独立执行；否则主代理另起验收过程，如实记录执行者。

## 使用闭环也是必需场景

按 [产品使用闭环](product-loop.md) 实际执行 `repeat_use`：连续两轮任务，记录可发现的继续路径和退出/恢复。product-designer 复核实际体验，code-review 的 Spec 轴检查 AC 是否漏掉基本路径；复用同批真实操作，不另造重复验收。技术功能通过但使用闭环失败，不得称完整可用。

## 验收范围与证据复用

先按 [高效交付](efficient-delivery.md) 将 AC 映射到操作及结果，并据改动影响确定复验范围。同一候选、同一次真实操作可同时支持实施票和最终验收，记录引用关系；文档未改变运行包时保留原验收。代码变更后，当前候选必需场景仍须真实执行，历史深测只能单列引用，不改写为当前实测。

## 固定候选包

记录版本/提交、构建命令、目录及哈希。发布前将最终 ZIP 解压到新测试目录并加载这一份，按影响复验。测试后包变化需重新关联证据，版本号相同不证明文件相同。

**默认必须使用 Playwright MCP 加载当前实际构建产物，完成从安装到结果的端到端验证。** 先读 [Playwright MCP 验收执行说明](playwright-mcp.md)，检查当前服务、浏览器、加载方式和原生入口能力。Playwright MCP 的 `--extension` 是连接已有浏览器的桥接方式，不是安装待测插件；不得虚构通用插件安装工具。未经用户选择不使用其日常浏览器。

Playwright MCP 缺失、不能加载实际插件或不能操作必需原生入口时，必须向用户说明具体缺口，询问是否安装/启用/修复 Playwright MCP，或选择已核实能够覆盖该缺口的受控替代。推荐的替代可包括具备扩展操作能力的 Chrome DevTools MCP、其他浏览器 MCP 或受控浏览器，但必须取得并保存用户的明确选择；等待期间关卡保持 `blocked`。不能静默换工具、跳过验收，或把人工步骤清单算成完成。已有明确选择和授权则沿用，不为同一环境反复询问。

从 [依赖准备](dependencies.md) 的路由取得 Playwright MCP 能力，或按用户已批准的替代完成准备后，按顺序执行：计算当前目录指纹 → 在独立测试配置中实际加载当前目录 → 核对扩展 ID、路径及版本 → 从工具栏 action、原生侧栏或实际菜单入口打开 → 执行核心动作并读取真实结果 → 关闭后重新从真实入口打开并核对状态 → 保存原始操作与结果证据 → 运行门禁 `check` 并保存 `gate-report.json`。原生入口、核心结果或重开步骤有一项缺失，门禁不得通过。跨浏览器重启等额外场景按产品承诺纳入。

| 验证层 | 证明什么 | 不能替代什么 |
| --- | --- | --- |
| 语法、类型、构建 | 编译及静态契约成立 | 真实操作 |
| 模拟 Chrome API 的逻辑测试 | 模拟条件下的业务逻辑 | 实际权限、浏览器事件、存储、剪贴板或原生入口 |
| 发布目录检查 | 检查器覆盖的结构、引用等 | 完整代码/数据审计、实际功能或商店审批 |
| 票内真实使用 | 当前功能从真实入口到结果可用 | 跨功能及线上安装 |
| 独立总验收 | 整合版本完整路径可用 | 商店实际分发状态 |
| 商店首用 | 目标用户安装线上版本并完成核心任务 | 所有网站/浏览器兼容承诺 |

## 按功能选矩阵

| 场景 | 观察结果 |
| --- | --- |
| 安装和真实入口 | 来源、ID、版本正确；从工具栏、侧栏或菜单真正打开 |
| 核心成功路径 | 代表性页面完成任务，核对文本/产出；复制后粘贴，下载后打开 |
| 关闭、重开、重复 | 保留/取消符合规格，重开浏览器应保存内容仍在，不意外覆盖 |
| 权限和页面边界 | 拒绝授权、内部页及不支持网页有正确反馈 |
| 内容和网络异常 | 实际涉及的空/长内容、远程失败、断网可恢复，保留完成成果 |
| 删除和升级 | 删除正确；隔离测试数据验证旧版迁移及旧功能，不覆盖真实用户数据 |
| 界面和键盘 | 小窗口、滚动、空态、焦点、键盘；有动效再检查减少动效，有设计基准再对照 |

把 popup 单独当普通页面打开、向普通标签页注入假的 `chrome` 对象、直接调用业务函数或直接写入存储，均不能作为原生核心路径通过证据。必须通过实际入口触发功能，核对真实产出；读取存储可补充诊断，不能代替界面保存操作。

有持久化承诺时，保存后须关掉原生弹窗再打开，核对同一内容；承诺跨浏览器重启保存时，在隔离测试配置中重启后再核对。复制后实际粘贴，标签页恢复后核对新标签页及网址，计时器核对真实后台恢复与到期状态。每项核心承诺均需当前文件的实际结果，不能只依据成功提示、截图或“挺好”。

缺少能力时先完成上述环境选择，按选择补齐受控环境，不能将人工步骤表交给新手后结束开发。只有已说明且无法自动化的原生环节确实必须本人操作时，才给当前一步并保留对应 `blocked` 状态；取得可核对的真实操作结果后由 AI 接回受控端到端验收。人工辅助不是工具选择或真实结果的豁免。沿用已有测试授权，不为同一测试环境内例行加载测试扩展、重载或检查反复请求确认；未经用户选择不切换到其日常浏览器，不为测试清空主浏览器数据。

实际操作:
预期结果:
实际结果:
方式和执行者: 自动 / 人工 / 辅助人工
证据: 截图、日志、导出结果等路径

## 机器门禁与真实证据

以下由 AI 在技能目录之外保存证据，并使用当前候选运行目录执行；输出报告必须使用新路径，不能覆盖旧证据。

```text
python3 <skill-dir>/scripts/acceptance_gate.py fingerprint <build-dir>
python3 <skill-dir>/scripts/acceptance_gate.py check <build-dir> --evidence <真实验收JSON路径> --report <新的gate-report.json路径>
```

`fingerprint` 输出对象原样放入真实验收 JSON 的 `candidate` 字段，只计算文件指纹，不生成通过记录。真实验收 JSON 使用以下契约，操作未发生时不得预填 `passed`：

| 字段 | 内容 |
| --- | --- |
| `schema_version` | `1` |
| `candidate` | 当前目录的 `fingerprint` 输出对象，包含全部运行文件及 SHA-256 |
| `environment` | 实际 `automation_provider`、`browser_name`、`browser_version`、`extension_id`、`installation_type`；默认服务为 `playwright-mcp`，安装方式为 `unpacked`、`store` 或 `enterprise` |
| `browser_choice` | 使用替代服务时必填；`default_provider: playwright-mcp`、与实际环境一致的 `selected_provider`、具体 `reason`，以及 `user_decision: {status: approved, evidence_path: ...}`；路径必须指向用户明确选择的原始记录，不能以 AI 自述代替 |
| `required_scenarios` | 至少含 `install`、`native_entry`、`primary_flow`、`reopen`、`repeat_use`，并加入规格中的其他必需场景编号 |
| `scenarios` | 实际场景列表；每项有唯一 `id`、与必需清单一致的布尔 `required`、`status`、`method`、非空步骤数组 `steps`、可观察的 `expected` 和 `actual`、证据数组 `artifactPaths` |
| 通过场景 | `status: passed`，`method` 必须为 `real_browser_tool` 或 `witnessed_manual`；后者仍须记录实际自动化服务和可核对的原生操作结果，不能豁免服务选择；模拟、静态检查不能使用这些方法值 |
| `native_entry.entry_kind` | 对应场景对象的 `entry_kind` 为实际入口：`native_action`、`context_menu`、`keyboard_command`、`native_side_panel` 或 `browser_extension_entry` |
| `artifactPaths` | 相对于真实验收 JSON 所在目录的真实证据文件路径；文件必须存在、非空且位于该目录内，不能指向验收汇总 JSON 自己 |

`repeat_use` 还须包含 `rounds`（至少两项，每项非空 `entry` 和 `outcome`）、`continuation`、`exit_or_recovery`，全部描述真实操作。旧报告缺该场景时不能通过新门禁，但不自动修改旧记录或重测已停止的例子。字段完整不证明体验良好，仍需核对实际 UI 与操作记录。

`reopen` 必须实际关闭并重新打开适用的插件入口，核对按规格应保留或清除的状态；有本地保存承诺则必须核对真实保存内容。跨浏览器重启作为额外必需场景记录，不能用简单重开弹窗替代。

`automation_provider` 默认只填 `playwright-mcp`。用户明确选择的替代值限于 `chrome-devtools-mcp`、`browser-mcp`、`controlled-browser`，并要求 `browser_choice.selected_provider` 与之相同。`user_decision.evidence_path` 相对于验收 JSON 所在目录，须指向该目录内真实、非空的原始用户选择记录；不得指向验收 JSON 自己，不得预写同意或以等待超时代替选择。可从已有会话复制用户实际选择并记录来源，不得改写为未发生的批准。

工具能力、受控浏览器配置和实际执行方式一并留证。加载或入口失败时记录失败并保持关卡 `blocked`，按已批准环境修复；需要更换服务时走用户选择流程。只有受控环境中无法自动化的原生环节才辅以实际原生操作，随后接回真实验证；不默认切换日常浏览器。门禁不能识别虚构证据，主代理仍须核对实际浏览器操作、产出及原始记录。

失败留记录 → 回实施票或新缺陷票 → **读取并执行 `diagnosing-bugs`**，复现并定位原因 → 修复 → 原失败和受影响路径复验 → 新证据回填。验收票不夹带新功能、不降低预期。

必需场景有当前包真实通过证据，并经上述门禁 `check` 返回 `gate_passed: true` 后才关闭；将生成的 `gate-report.json` 路径回填任务。缺报告、候选文件指纹已变化、门禁拒绝或未执行均不能关闭。门禁只核验证据契约，不能把虚构或模拟记录变成真实通过。

无关场景写不适用并说明与规格的关系；安装、原生入口、核心路径和重开不得以工具不足标不适用。必需场景失败先修复；能力不足必须完成环境选择并继续补齐，等待用户选择或确实依赖本人操作时交付状态保持 `blocked`。用户拒绝安装且未选可用替代时，如实保留未验收状态。可以继续无依赖的材料工作，但不能用材料完成冲抵验收。反馈精确说检查了哪些、还剩哪一步，不报笼统全部通过。
